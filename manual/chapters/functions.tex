\chapter{Function Reference}
\label{app:functions}

This appendix lists every function the engine registers, grouped as
\fn{(list-deffunctions)} groups them. \fn{(usage name)} prints a function's
usage string at the shell.

Arguments written \fn{<value>} may be literals, bound variables or nested
function calls. A trailing \fn{+} means one or more, \fn{*} zero or more,
and square brackets mark an optional argument. Unless a description says
otherwise, a function that takes numbers accepts integers and floating
point values and returns a \fn{BigDecimal}; comparison functions return a
boolean.

\begin{note}
A top-level expression that names a function the engine does not have
evaluates to \fn{false} without an error message; nested inside another
call, an unknown function is an error. In particular there is no \fn{run}
(use \fn{fire}), no \fn{load} (use \fn{batch} or \fn{load-facts}) and no
\fn{deffacts}.
\end{note}

\section{Math functions}

The arithmetic and comparison operators are aliases of named functions:
\fn{+} is \fn{add}, \fn{-} is \fn{subtract}, \fn{*} is \fn{multiply},
\fn{/} is \fn{divide}, \fn{**} is \fn{pow}, \fn{>} is \fn{greater},
\fn{>=} is \fn{greaterOrEqual}, \fn{<} is \fn{less}, \fn{<=} is
\fn{lessOrEqual}, \fn{=} and \fn{==} are \fn{eq}, and \fn{<>} and
\fn{!=} are \fn{neq}. Either spelling works. Comparisons take any number
of arguments and test each adjacent pair.

\section{Type functions}

\fn{stringp} and \fn{lexemep} agree. A number written with a decimal
